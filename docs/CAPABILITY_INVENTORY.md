# LEO Design Rationale — Capability Inventory (Hermes / OpenClaw)

Classification values: `native`, `compatible-adapter`, `official-integration`, `independent-reimplementation`, `deferred`.

**Status rule (2026-11-19):** the "Verification status" column records **local
LEO evidence**, kept explicitly distinct from `Source-verified upstream`, which
means only official upstream documentation was reviewed. Local evidence is one
of: `unit-tested` (real local code path, offline test), `mock-tested` (injected
client/fake backend — **not** a working live integration), `live-blocked`
(local path exists but delivery/call needs credentials, host env or
infrastructure), or `not implemented`. A `tests/...py` citation names a file
that exists in this repository. The model gateway is the one env-conditional
exception: live-capable when the host supplies `ANTHROPIC_AUTH_TOKEN` and
`LEO_OPENCODE_SESSION`, mock fallback otherwise.

**Correction after deep testing (2026-11-18):** both SKILL.md adapters are
*metadata-import tested, execution untested and unsupported*. A shared parser
does not imply runtime compatibility: none of 327 real upstream SKILL.md files
was executable in LEO, availability gates are retained as inert `gates` data,
and imported scripts are never run. Do not read "compatible-adapter" below as
functional execution. Evidence:
[skill compatibility test](../the upstream research notes).
Sources and license details: [research report](RESEARCH_HERMES_OPENCLAW.md).
