# LEO Design Rationale — Hermes Agent and OpenClaw Research

**Retrieved:** 2026-11-18. **Scope:** official repositories, official documentation sites, and license files only. No LEO integration has been implemented or tested as part of this research.

## Corrections after source-level verification (2026-11-18)

Later source audits at pinned commits supersede several doc-level claims below:

- Hermes `delegation.max_iterations` defaults to **250**, not 50
  (`tools/delegate_tool.py:108` at `b076b585…`).
- The three prompt tiers are assembled in `agent/system_prompt.py::build_system_prompt_parts`,
  not `agent/prompt_builder.py`.
- Tool/toolset counts in this document (70–85 tools, ~28 toolsets) do not match
  the pinned commit (45 literal tool registrations, 57 static toolset entries).
- Hermes webhook default host is `None` (binds all interfaces), not literal `0.0.0.0`.
- In OpenClaw, `cron` is primary and `automations` is its alias — the reverse of
  the earlier wording.
- "Similar skill shape suggests a shared loader" is too optimistic: metadata
  import works for a subset; none of 327 tested real skills was executable in
  LEO. See [deep research](../the upstream research notes).

Full evidence: [Hermes source audit](../the upstream research notes)
and [OpenClaw source audit](../the upstream research notes).

## 2. Hermes Agent — architecture and capabilities

Architecture (source: [architecture](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/architecture.md), [agent loop](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/agent-loop.md)): Python `AIAgent` facade in `run_agent.py`; loop in `agent/conversation_loop.py`; prompt assembly in `agent/prompt_builder.py` with `stable`/`context`/`volatile` tiers; three API modes (`chat_completions`, `codex_responses`, `anthropic_messages`); central tool registry (`tools/registry.py`, ~70–85 tools in ~28 toolsets per different docs pages); persistent gateway process; cron scheduler; SQLite/FTS5 persistence; provider resolver with OAuth, key pools, aliases, and `fallback_providers`; ACP adapter; CLI/TUI/desktop frontends.

Concrete documented capabilities:

- **Skills:** `SKILL.md` per skill directory, optional `scripts/` and `references/`; frontmatter includes `name`, `description`, `version`, `author`, `license`, `platforms`, plus `metadata.hermes` gates (`requires_toolsets`, `requires_tools`, `config`, `blueprint`, etc.). Bundled under `skills/`, official optional under `optional-skills/`, user skills under `~/.hermes/skills/`; CLI `hermes skills install`. README claims compatibility with the agentskills.io open standard; the authoring doc does not restate that claim. Skill creation/improvement is part of the advertised learning loop. Sources: [creating skills](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/creating-skills.md), [skills catalog](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/skills-catalog.md), [README](https://github.com/NousResearch/hermes-agent/blob/main/README.md).
- **Memory:** built-in `MEMORY.md` / `USER.md`, agent-curated writes under character limits, flushed before compression; pluggable single-active external `MemoryProvider` with `prefetch`, `sync_turn`, `on_pre_compress`, `on_memory_write`, tool schemas; FTS5-backed `session_search` (no LLM call) over `~/.hermes/state.db`; README also mentions Honcho dialectic user modeling. Sources: [memory provider plugin](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/memory-provider-plugin.md), [sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md).
- **Subagents:** `delegate_task` creates isolated sessions with own terminal/toolset; only final summary returns; default `delegation.max_iterations` 50. Plugin API `ctx.subagent_lifecycle.launch(...)` with status/wait/cancel/steer/result/reconnect, opaque versioned handles, narrowed toolsets, no post-restart reconnect. Sources: [tools reference](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md), [subagent lifecycle API](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/subagent-lifecycle-api.md).
- **Tools / execution:** toolsets gate availability by platform, credentials, and session type; multi-tool turns run concurrently except interactive tools; dangerous-command approval modes `smart`/`manual`/`off`, hardline blocklist, user deny globs; `execute_code` calls tools from Python; MCP tools named `mcp__<server>__`. Source: [tools reference](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md), [security](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/security.md).
- **Terminal:** built-in backends `local`, `docker`, `ssh`, `modal`, `daytona`, `vercel_sandbox`; plugin backends such as Singularity/Apptainer; background jobs, completion notifications, plugin API `ctx.register_terminal_environment_provider(...)`, `plugin.yaml` with `kind: backend`. Container backends skip dangerous-command approval because the container is the boundary. Sources: [terminal environment plugin](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/terminal-environment-plugin.md), [architecture](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/architecture.md).
- **Browser:** `browser_exec` (Python helper calls, state persists between calls), `browser_cdp` (CDP), `browser_dialog`, `browser_vault`; local Chromium, cloud/Browserbase, attached CDP; per-task CDP supervisor handles native JS dialogs and out-of-process iframes, with `browser.dialog_policy` (`must_respond`, `auto_dismiss`, `auto_accept`). Source: [tools reference](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/reference/tools-reference.md), [browser supervisor](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/browser-supervisor.md).
- **Scheduling:** cron jobs are agent prompts (not shell crontabs) with relative/interval/cron/ISO schedules, pre-run scripts, attached skills, `origin`/platform/bot-chat delivery, `[SILENT]` suppression; CLI `hermes cron create|list|...` and chat `/cron add`. Each run gets a fresh agent session. Source: [automate with cron](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/guides/automate-with-cron.md).
- **Context / sessions:** pluggable `ContextEngine` replaces `ContextCompressor` (one active, opt-in via `context.engine`); preflight compression above 50% of context window, gateway auto-compression above 85%, last 20 messages preserved by default; `message_uid` tracking; Anthropic cache breakpoints. SQLite `state.db` in WAL mode holds messages, metadata, FTS5; resume via `hermes -c`/`-r`; lineage via `parent_session_id`, `/branch`; retention default 90 days but pruning off by default. Sources: [context engine plugin](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/context-engine-plugin.md), [sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md).
- **Messaging gateway:** single long-lived process; 20–25+ adapters (Telegram, Discord, Slack, WhatsApp local bridge and Cloud API, Signal, email, SMS, Matrix, Teams, Feishu, etc.); deterministic session keys `agent:{namespace}:{platform}:{chat_type}:{chat_id}`; allowlist/pairing authorization with default deny; `/handoff` moves a CLI session to a platform. Sources: [gateway internals](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/gateway-internals.md), [sessions](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md).
- **Webhooks / remote:** HTTP ingress adapters `api_server`, `webhook`, `msgraph_webhook`; webhook routes at `/webhooks/<route-name>` on `0.0.0.0:8644` by default, HMAC signatures (GitHub/GitLab modes), per-route rate limit (30/min) and 1-hour dedupe, 1 MB body cap; authenticated `/api/ws` uses short-lived single-use loopback tickets. Remote operation is via SSH clients, messaging channels, or cloud hosts, not a dedicated remote-access product. Sources: [gateway internals](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/gateway-internals.md), [GitHub PR webhook guide](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/guides/webhook-github-pr-review.md).
- **Models:** first-class providers include Nous Portal, OpenRouter, Anthropic, OpenAI, Gemini/Vertex, Bedrock, Azure AI Foundry, xAI, DeepSeek, Fireworks, MiniMax, Kimi, z.ai, Qwen, HF, NVIDIA, LM Studio/Ollama/vLLM/SGLang/llama.cpp; custom OpenAI-compatible endpoints; ≥64k context requirement for tool use; ordered `fallback_providers`. Source: [providers](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/integrations/providers.md).
- **Extensions:** directory plugins with `plugin.yaml` discovered from user/project paths and pip entry points; tools self-register at import; single-select memory/context-engine plugin slots; MCP; platform adapters; terminal-environment backends; ACP; optional skills; catalog installs via `manage_catalog` with commit pinning/security scanning. Source: [architecture](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/architecture.md).

## 3. OpenClaw — architecture and capabilities

Architecture (source: [architecture](https://github.com/openclaw/openclaw/blob/main/docs/concepts/architecture.md)): one long-lived Gateway daemon per host owns channels, sessions, tools, auth, events, and a typed WebSocket API (default `127.0.0.1:18789`, JSON Schema-validated frames, nonce-signed device identity, optional pairing). Clients (macOS app, CLI, Control UI, TUI, automations) and `role: node` companions connect over that socket. `openclaw gateway` runs in the foreground under launchd/systemd; one `GatewayScheduler` drives maintenance/cron. Security posture in the README: "trusted gateway, untrusted execution, policy enforced by code."

Concrete documented capabilities:

- **Skills:** directory with `SKILL.md` (required `name` + `description` YAML frontmatter), optional scripts/references/assets, `metadata.openclaw.requires.*` gating; seven documented precedence tiers (workspace, project `.agents/skills`, personal `~/.agents/skills`, managed, workshop, bundled, extraDirs/plugin); snapshot per session with watchers; `$name` references, slash invocation, `skills_search`/`skills_read`; AgentSkills spec; ClawHub distribution via `openclaw skills install`, verification via `openclaw skills verify`. Third-party skills explicitly treated as untrusted code. Source: [skills](https://github.com/openclaw/openclaw/blob/main/docs/tools/skills.md).
- **Memory:** Markdown-only workspace memory (`USER.md`, `MEMORY.md`, `memory/YYYY-MM-DD.md`, `DREAMS.md`) with bootstrap loading and silent pre-compaction flush; `memory-core` SQLite engine, `memory_search` (keyword + optional embeddings), `memory_get`, optional PostgreSQL; plugins Honcho, LanceDB, `memory-wiki`; imports from Codex/Claude Code/Hermes stored separately. Source: [memory](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory.md).
- **Context:** context engines with ingest/assemble/compact/after-turn hooks, token budget, `ownsCompaction` flag, `plugins.slots.contextEngine` (default `legacy`), tool-result trimming independent of engine, quarantine/fallback to `legacy`. Source: [context engine](https://github.com/openclaw/openclaw/blob/main/docs/concepts/context-engine.md).
- **Subagents:** background runs with own `agent:<id>:subagent:<uuid>` session; tools `sessions_spawn`, `sessions_yield`, `subagents`; isolated by default, optional `context: "fork"`; cheaper model config `agents.defaults.subagents.model`; default loss of session/message tools; announce chain for results; nesting/spawn limits. Source: [subagents](https://github.com/openclaw/openclaw/blob/main/docs/tools/subagents.md).
- **Tool execution / terminal:** `exec` with `command`, `workdir`, `host`, `yieldMs`, `background`, `durable`, `pty`, `elevated`, `ask`; approval ladder `deny`/`allowlist`/`ask`/`auto`/`full`; `process` tool for poll/log/write/kill; durable jobs survive Gateway restarts via systemd/launchd on supported hosts (limits: 16/session, 64/gateway). Sandboxing is opt-in, Docker default (also Podman/SSH/OpenShell/Crabbox); Gateway stays on host, only tool execution moves; docs state it is "not a perfect security boundary." Sources: [exec](https://github.com/openclaw/openclaw/blob/main/docs/tools/exec.md), [background process](https://github.com/openclaw/openclaw/blob/main/docs/gateway/background-process.md), [sandboxing](https://github.com/openclaw/openclaw/blob/main/docs/gateway/sandboxing.md).
- **Browser:** separate managed Chrome/Brave/Edge/Chromium profile controlled by a loopback service in the Gateway; tab/snapshot/click/type/screenshot/PDF actions; Playwright-backed actions and remote WebSocket CDP providers (Browserless, Browserbase, Notte); `user` profile can attach via Chrome DevTools MCP; SSRF policy and control-API auth documented. Source: [browser](https://github.com/openclaw/openclaw/blob/main/docs/tools/browser.md).
- **Computer use / nodes:** macOS uses Peekaboo or CUA (Accessibility + Screen Recording permissions); Windows/Linux use experimental `cua-computer`; one action per call (screenshot, click, drag, type, keys, wait), `frameId`-scoped coordinates; nodes advertise `computer.act`/`screen.snapshot`, require pairing approval, and can expose camera/screen/location; on-screen content is untrusted. Sources: [computer use](https://github.com/openclaw/openclaw/blob/main/docs/nodes/computer-use.md), [architecture](https://github.com/openclaw/openclaw/blob/main/docs/concepts/architecture.md).
- **Automation / webhooks:** Gateway `openclaw automations` (`openclaw cron` alias) supports one-shot ISO and recurring cron schedules, agent/command/script payloads, main/current/isolated sessions, chat/webhook/no-op delivery; internal hooks, plugin `api.on(...)` hooks, and HTTP webhook ingress; hook handlers are sequential, trusted, non-sandboxed, with no durable queue or exactly-once guarantee. Sources: [cron jobs](https://github.com/openclaw/openclaw/blob/main/docs/automation/cron-jobs.md), [hooks](https://github.com/openclaw/openclaw/blob/main/docs/automation/hooks.md).
- **Messaging gateways:** Telegram (grammY, long polling or webhook, pairing default, forum topics, exec approvals), WhatsApp (Baileys WhatsApp Web, `@openclaw/whatsapp` plugin, creds at `~/.openclaw/credentials/whatsapp/...`, pairing, media), Discord (official Discord gateway bot, guild/channel allowlists, threads, voice); also Slack, Signal, iMessage, Google Chat, Teams and 20+ others. Sources: [telegram](https://github.com/openclaw/openclaw/blob/main/docs/channels/telegram.md), [whatsapp](https://github.com/openclaw/openclaw/blob/main/docs/channels/whatsapp.md), [discord](https://github.com/openclaw/openclaw/blob/main/docs/channels/discord.md).
- **Sessions:** Gateway-owned SQLite at `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite`; DM scope `main`/`per-peer`/`per-channel-peer`/`per-account-channel-peer`, group scope `per-group`, identity links, reset by hour/idle, maintenance/pruning, session attachment across UI/CLI/harness. Source: [session](https://github.com/openclaw/openclaw/blob/main/docs/concepts/session.md).
- **Remote access:** SSH port forwarding, Tailscale Serve/tailnet WebSocket, identity-aware proxies (Cloudflare Access), OpenClaw ID relay with single-use invites, macOS remote mode; non-loopback binds require auth; prefer loopback + tunnels, `wss://` for public hosts. Source: [remote](https://github.com/openclaw/openclaw/blob/main/docs/gateway/remote.md).
- **Models:** provider integrations are bundled plugins (OpenAI, Anthropic, Codex OAuth, Google, xAI, OpenRouter, MiniMax, Moonshot, etc.) plus local runtimes (llama.cpp, LM Studio, Ollama, vLLM, SGLang); `models.providers`, key rotation, failover. Source: [model providers](https://github.com/openclaw/openclaw/blob/main/docs/concepts/model-providers.md).
- **Extensions:** native plugin root manifest `openclaw.plugin.json` requiring `id` and inline `configSchema` (JSON5 syntax); `register(api)` entrypoint; `api.register*` surfaces for tools, channels, providers, CLI commands, services, routes, hooks, MCP servers; native plugins load in-process and are not sandboxed; bundles are metadata/content packs. Sources: [plugin manifest](https://github.com/openclaw/openclaw/blob/main/docs/plugins/manifest.md), [plugin architecture](https://github.com/openclaw/openclaw/blob/main/docs/plugins/architecture.md).

## 4. Cross-ecosystem comparison relevant to LEO

| Area | Hermes | OpenClaw | LEO implication |
|---|---|---|---|
| Unit of extension | `SKILL.md` + `metadata.hermes`; `plugin.yaml` plugins | `SKILL.md` + `metadata.openclaw`; `openclaw.plugin.json` plugins | Similar skill shape suggests a shared LEO skill loader plus two frontmatter adapters; plugin systems are *not* interchangeable. |
| Memory | Markdown files + single active external provider + FTS5 session store | Markdown files + SQLite/embedding search + replaceable memory plugin | Converge on Markdown durable memory + indexed sessions; provider adapters optional. |
| Subagents | `delegate_task` and versioned lifecycle handles | `sessions_spawn`/`sessions_yield` with announce chain | Both require strict isolation budgets and explicit result handoff; no need to reuse either runtime. |
| Execution | Tool approvals + multiple remote/container terminal backends | Opt-in sandbox + exec approval ladder + durable background jobs | LEO should treat approval/policy as native, backend-specific isolation as adapters. |
| Browser | CDP supervisor, Python `browser_exec`, dialog/OOPIF handling | Managed browser profile, Playwright/CDP, nodes | Shared CDP-based adapter feasible; credentials/profiles must stay per ecosystem. |
| Automation | Cron agent prompts delivered to channels; HMAC webhooks | Automations scheduler + internal/plugin hooks + HTTP webhook ingress | Native scheduler + signed webhook ingress; hook semantics differ (Hermes deliver-oriented, OpenClaw event-oriented). |
| Gateway | Messaging-first multi-platform gateway | WebSocket control plane with channels/nodes/clients | LEO needs a single internal control plane with separate channel adapters, not two gateways. |
| Security | Default-deny pairing, approvals, hardline blocklist, SSRF guards | Pairing, tool policy, opt-in sandbox, explicit remote-auth rules | Untrusted inbound content must never inherit operator authority in LEO. |

## 5. Explicitly unverified or uncertain

- No LEO integration test exists; every inventory row is documented/planned/blocked, never "working."
- WebSearch was unavailable; no independent search-engine corroboration was obtained. Repository identity is confirmed by GitHub API metadata and official docs cross-links.
- Hermes README claims agentskills.io compatibility; the detailed skill-authoring page does not mention it. The standard's exact spec and the compatibility claim were not verified.
- Hermes adapter counts differ across docs ("20+", "25+"); exact current count unverified.
- Real behavior of Hermes/OpenClaw at runtime (latency, reliability, provider quirks, sandbox escapes) was not tested; only documentation was read.
- OpenClaw plugin architecture page was truncated by the fetch tool before its final ~2k characters; some tail content was not read.
- Third-party skill/plugin licenses, ClawHub trust envelopes, Terms of Service for WhatsApp Web/Baileys and remote browser vendors, and current release/version numbers were not verified.
- No conclusion is drawn about whether Hermes skills can be loaded byte-for-byte by OpenClaw or by LEO; frontmatter shapes differ (`metadata.hermes` vs `metadata.openclaw`).
